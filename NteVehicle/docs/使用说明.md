# NteVehicle 2.7 改装版 · 使用说明(最终版)

这是官方 NteVehicle(2.7,v0.11.1)的本地改装版:找回官方重写时弄丢的
改装记忆、修复 1.5 枚举导致的整类改装丢失,并新增特效白名单(霓虹域界/
拟真态火焰常驻)、当前载具实时改装等能力。逐版本改动见
`..\05_2.7迁移执行记录.md`。

## 一、安装

1. 退游戏 + 退 launcher;
2. 运行时 `plugins\NteVehicle\` 里的官方 `plugin.dll` 改名为
   `plugin.dll.official-0.11.1` 留作回滚;
3. 把本文件夹的 `plugin.dll`、`manifest.json`、`locales\zh-CN.json`
   三个文件覆盖进去;
4. **不动 `profile\`**(插件的布局校验靠它);
5. 进游戏看到「Vehicle Control」菜单即成功。

> 分享给朋友:整个 `NteVehicle-改装版` 文件夹打包即可。
> 对方要求:Anomaly 2.7+、同版本游戏。**不要带**自己的记忆和白名单文件(个人数据)。

## 二、★ 标准使用流程(每天/每辆车照这个来)

> 背景:游戏 2.7 把新车的升级目录改为**开一次改装店才从服务器拉取一次**——
> 插件读的是本地表,所以"开店"是让插件看到完整列表的前提。

| 步骤 | 操作 | 为什么要这一步 |
|------|------|----------------|
| 1 | 游戏里**打开那辆车的改装店**(翻一圈分类) | 触发服务器把该车的完整物品目录拉到本地表 |
| 2 | 插件改装页点**「重新读取改装数据」** | 插件有缓存,不点看不到新拉取的行 |
| 3 | 在插件列表里**选件** | 此时列表 = 游戏商店的完整目录 |
| 4 | 点**「改装召唤」** | 应用配置召出车辆(0.11.8 起只改你选的槽位,其余保持服务器原状) |
| 5 | (可选)点**「读取当前车辆已装模块」** | 验证应用结果 |

- 换一辆车 = 重复步骤 1-2(每辆车的目录各自拉取,落地后持久保留);
- 「扫描全部数据表」**不在日常流程里**——只在怀疑有物品缺失时做一次排查;
- 未拥有的车辆:商店目录受限(游戏按拥有权下发),是游戏行为不是插件问题;
- 解锁新物品后:同样走步骤 1-2,列表里就会出现,直接选装。

### ★ 实时改装(0.11.22 完整版,改装调校页)

不用重新召唤、不用切页,**在本页完成读取→选件→应用**(行驶中也可以,
模块重建走游戏自己的 UpdateAllModulesWithIDs——与涂装同级的真函数):

1. 坐进/驾驶目标车;
2. 点**「读取当前载具改装(并同步选车)」**——插件选车自动切到这辆车并
   加载它的改装目录;
3. **在本页下方的分类列表里直接点选**要改的件:全部改装类别 + 霓虹域界/
   拟真态火焰 + **涂装**(点涂装=立即应用),已选项带 [已选] 标记
   (改装召唤页的选项同样标注 [已选]/[默认]);
4. **点选即自动应用**——0.11.24 起每点一次改装选项,插件立即把当前选择应用到这辆车(应用按钮已取消,无需再点);
 5. 「把当前车特效加入白名单」= 校准工具(精确编号采集+成对推导);
    「保存当前车辆状态为该车记忆」= 覆盖保存该车记忆,改装召唤时复现。

**漂移轮换**(0.11.25,实时页顶部右侧四个按钮):
- 「烟雾轮换:开/关」「痕迹轮换:开/关」**独立开关**(关 = 用改装页所选的件);
- 「烟雾范围(x)」「痕迹范围(x)」点开勾选列表,✓ 的件参与轮换,
  x = 当前勾选数(默认全部);
- 开着时**每按一次 Shift,0.3 秒后自动切换到下一个**烟雾/痕迹并立即应用——
  行驶中甩尾随时换效果;轮换从当前装备的件继续;
- **全局通用 + 持久化**:开关与范围一套设置对所有车生效,保存于\n  `drift-config.cfg`(state 目录,与其它记忆同目录,变更即时落盘,\n  重启不丢);

**进阶传动参数**(同页,直接数值滑条,拖动即生效):**最高限速 (km/h)** +
倒车极速 + 升档转速/降档转速/换挡耗时/齿比总比/传动效率——**普通/舒适
两套独立编辑**(顶部按钮切换当前编辑模式),「游戏实时值」行对照;写入后
插件自动调用游戏的 ReSetupEngineAndTransmission 把新配置推进物理模拟。
**最高限速滑条**:显示目标限速 km/h,**下限 = 原厂极速(1.0x)**,**上限 =
350 km/h**,倍率程序实时换算并显示(内核仍是倍率机制);原厂极速未读取时
回退倍率滑条。扭矩倍率等其他倍率滑条也都在本组(拖动即生效)。

**每车调校记忆**(tuning-memory.cfg,与改装记忆同目录;0.11.22 起双模式
+倍率合体保存):
- 「**保存当前调校为该车记忆**」= 双模式传动 + 四个倍率一起存;
- 上车/召唤**自动加载**(插件召唤的车按召唤页选中的车型对号);
- 「**恢复默认调校**」= 双模式回原厂值 + 四个倍率回 1.0,滑条同步回位
  (保存的记忆保留,重新上车会再次自动加载);
- 不想要某辆车的保存调校:上车点恢复默认,或直接拖滑条覆盖。

**日志**:所有操作状态和报错自动记录;「导出日志」导出后**状态栏显示
完整路径**——本机实际在游戏目录 `...\Binaries\Win64\Anomaly\state\` 下
(不是 NOMANSKYTOOLS 副本里),报障时把那个 txt 直接发来。

**诚实边界**:模块/特效/调参应用都是**客户端视觉与本地模拟**——服务器
清单不动,重新登录/改装召唤/商店操作后服务器状态回来;**永久变更**仍走
游戏商店或改装召唤;插件召唤的客户端车不支持实时涂装(其 VehicleID 为空,
会明确报错),其调校记忆按召唤页选中车对号。

## 三、相对官方 0.11.1 的改动

| # | 改动 | 原因 |
|---|------|------|
| 1 | 改装类型过滤 `>=27` → `>=28`(扫描+召唤+插件侧三处) | 1.5 新增 ExhaustSmoke=27,官方照搬旧哨兵值整类丢弃 |
| 2 | 单条异常跳过该行,不清空整个目录 | 官方一条坏行 = 整车列表空白 |
| 3 | 改装记忆(customization-memory.cfg,兼容 2.6 格式) | 官方重写时丢失 |
| 4 | 取证三件套:catalog-dump / catalog-dropped-rows / datatables-inventory | 定位「游戏有、插件无」的改装项 |
| 5 | 每车召唤快捷键(绑定+一键召唤+H\| 行持久化) | 官方重写时丢失 |
| 6 | 「读取当前车辆已装模块」按钮 | 云游戏方案的核心读取器 |
| 7 | 「扫描全部数据表」按钮 + CityShopExtensionData 探针 + 丢弃行显示名 | 数据源排查 |
| 8 | 白名单机制(allowed-extra-modules.cfg,支持 `ID#编号`) | 应用不在本地目录的模块 ID |
| 9 | 召唤以车辆当前服务器 loadout 为底,不再用目录默认件 | 防止覆盖服务器升级件(曾发生的事故,见 05 §11) |
| 10 | 白名单选项按选中车辆过滤 + 特效显示官方名(霓虹域界/拟真态火焰) | 0.11.14:防跨车误点;ID 太吵 |
| 11 | 「当前载具改装」:读取+应用改装到正乘坐的车(OnRep 机制) | 0.11.15:不用重新召唤,即时改当前车(客户端视觉) |

## 四、保存机制(两套存储,别混淆)

| 存储 | 在哪 | 存什么 | 稳定性 |
|------|------|--------|--------|
| **改装清单** | 游戏服务器,绑定账号+车辆 | 每辆车当前装备的模块 ID | **永久**:重启/换客户端/重装都不掉 |
| **货架(列表)** | 本地数据表 | 商店/插件"显示哪些物品可选" | **波动**:上架下架跟着服务器缓存走 |

「一会好一会坏」= 货架在变,**装上车的东西在服务器清单里永不掉**。918 的
霓虹烟雾就是证明——货架下架了它照样在冒。

**文件位置**(都在 `Anomaly\state\plugins\anomaly.nte-vehicle\`):
- `customization-memory.cfg` —— 插件记忆(每辆车选过的件,改装召唤自动应用);
- `vehicle-selection.cfg` —— 记住上次选的车型;
- `allowed-extra-modules.cfg` —— 特效白名单(**只服务霓虹域界/拟真态火焰**,
  七辆车已常驻预置,一行 `<类型>|<模块ID>`);
- 其余 `*-时间戳.txt` —— 诊断文件,可随意删。

**白名单规则**(0.11.17 起):
1. 白名单**只服务两个特效**——插件里只显示「霓虹域界」「拟真态火焰」
   两个按钮,且只显示**当前选中车辆自己的**;升级件一律走目录/记忆,
   不出现在白名单区;
2. **特效已常驻预置**:七辆车(016/017/021/026/037/038/060a)的两个特效
   直接写在白名单里,**开插件就能看到、随时能用**,不需要先"识别";
   918 用验证过的 `#11` 形式,其余六辆用当时验证过的无编号形式——
   每辆车各自的条目,不共用编号;
3. **自助收录仍可用**:坐进哪辆车(停稳)→ 改装调校页点
   **「把当前车特效加入白名单」**——按 FName 精确采集并自动补另一个,
   同基础名旧条目自动升级成精确编号;
4. 新车要上特效:先在游戏里装上(云游戏或商店),再点收录即可。

**按钮分两类**:「扫描全部数据表」「重新读取改装数据」「读取当前车辆已装模块」
「探测候选特效 ID」四个是**纯读取/诊断**(产生的 txt 可随意删);
「保存当前车辆状态为该车记忆」「把当前车特效加入白名单」「把已选改装应用
到当前载具」和「改装召唤」才**写状态/写文件**
(改装召唤写服务器清单 + 更新记忆文件)。

## 五、版本升级迁移(★ 所有相关文件地址,一个都别弄丢)

**你机器上真正在跑的 Anomaly 在游戏目录里**(NOMANSKYTOOLS 那份是副本,
插件由 launcher 同步过去;下面全部路径都以游戏目录为准):
`D:\Neverness To Everness\Client\WindowsNoEditor\HT\Binaries\Win64\Anomaly\`

**① 插件本体**(更新插件 = 覆盖这里的三件,profile 不动):
- `Anomaly\plugins\NteVehicle\plugin.dll`
- `Anomaly\plugins\NteVehicle\manifest.json`
- `Anomaly\plugins\NteVehicle\locales\zh-CN.json`(+ `profile\` 不动)

**② state 记忆文件**(都在 `Anomaly\state\plugins\anomaly.nte-vehicle\`,
换新 runtime 时**手动复制到新位置的同一相对路径**):
- `customization-memory.cfg` —— 每车改装记忆(含快捷键绑定);
- `vehicle-selection.cfg` —— 上次选的车型;
- `allowed-extra-modules.cfg` —— 特效白名单(七辆车常驻);
- `tuning-memory.cfg` —— 每车调校记忆(双模式+倍率,0.11.21 起);
- 其余 `*.txt`(catalog-dump / current-vehicle-modules / plugin-log 等)
  = 诊断文件,可丢。

**③ 插件源注册**(如果已上架插件源):
- `Anomaly\plugin-repositories.json` —— 里面那行你的 pluginmaster.json URL。

**一键迁移脚本**:`D:\NTEtools\Anomaly版本升级迁移\迁移改装记忆到新版本.bat`
—— 复制改装记忆/车型选择/白名单(脚本清单**尚未包含** tuning-memory.cfg
与游戏目录路径,迁移后请手动核对其余文件;下轮脚本升级会补齐)。
迁移后如果新版本改了插件 ID,再运行一次官方的 `Migrate-Plugin-Ids.cmd`。

## 六、已知边界(诚实声明)

- 2.6 的四个 Core 二进制补丁在 2.7 全部作废(官方用运行时反射,不需要了);
- 云上应用的特效在 PC 端的视觉表现取决于 PC 客户端是否有特效资源;
- 应用未拥有的付费内容有账号风险(服务端校验),知情选择;
- 「当前载具改装」是客户端视觉应用,重登后回服务器状态(永久变更走商店);
- 官方后续更新 NteVehicle 时按 `Local fix/Local feature` 标记重做
  (逐文件改动表见 `..\05_2.7迁移执行记录.md`)。
